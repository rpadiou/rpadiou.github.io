# Site context
Personal academic site of Raphaël Padiou, https://rpadiou.github.io. Plain HTML and CSS, hosted on GitHub Pages, **no build step**. KaTeX is self-hosted; the only other JS is in `assets/js/` and `sketches/mwu-rps/anim.js`.
**Never change the appearance** (layout, colors, fonts, spacing, either theme, desktop or mobile) unless explicitly asked. Metadata, scripts and docs changes must leave every pixel identical.
`README.md` explains day-to-day editing (Latest list, formulas, CV preview, CSS cache `?v=`).

# Conventions
- **Titles**: home = `Raphaël Padiou`; every other page = `<Title> — Raphaël Padiou` (em dash). `og:title` and `twitter:title` equal `<title>`; `og:description` equals the meta description (≤ 160 characters, unique per page).
- **Head of every page**: title, description, canonical (`dir/` for `dir/index.html`, `x.html` otherwise), `og:*` (type, site_name, title, description, url, image, image:alt), `twitter:*` (card, title, description, image, image:alt). Copy the head of an existing page. Home also has the Person JSON-LD.
- **One `<h1>` per page** (the name in the sidebar); article titles are `<h2 class="sk-title">`. Every `<img>` has a descriptive non-empty `alt`, plus `width`/`height`.
- **Project or sketch page** (`projects/<name>/index.html`, `sketches/<name>/index.html`; copy `sketches/mwu-rps/`): `<h2 class="sk-title">`, `<p class="pdate sk-date">Posted … · updated …</p>`, `<ol class="sk-toc">`, `<div class="sk-body">` with numbered `<h3 class="sk-sec" id=…>` sections (plain words first, then the technique), figures as `<figure><img><figcaption>`, then `<h3 class="sk-h" id="refs">References</h3>` and links to paper or code. Code lives in `code/` (uv project, `uv run`). Projects keep a generic name in `<span class="pname">` next to the title.
- **Style and figures**: colors and font are CSS variables at the top of `assets/css/style.css` (accent `#1f4e8c`). Figures are matplotlib PNGs (DejaVu Sans, dpi 160, white background, spines top/right hidden), colorblind-safe palette: red `#d55e00`, green `#009e73`, foreground `#111111`, grey `#8a8a8a`, faint `#d9d9d9`. Direct labels on the figure rather than legends; generated by the script in the page's `code/` folder.

# Checklist: new page or big update
1. Add the SEO tags as on existing pages (see Conventions).
2. Add the page to the list of its section (`projects.html` or `sketches/index.html`) and, for a new or updated article, to Latest in `index.html` (README).
3. `python3 scripts/make_sitemap.py` then `python3 scripts/site_check.py`.
4. Fix every ERROR (and read the warnings) before saying the work is done.

# Checklist: audit
1. `python3 scripts/site_check.py`.
2. Screenshot the modified pages (desktop 1440 px and mobile 390 px, light and dark) with Playwright, compare with the previous state, report any visual difference.
3. Report every deviation found, even minor.

# Rules
- Never say a task is finished until `site_check.py` is entirely OK (0 errors).
- `scripts/hooks/pre-push` runs `make_sitemap.py` then `site_check.py` and blocks the push on errors, or when it had to regenerate `sitemap.xml` (commit it, push again). Install once: `git config core.hooksPath scripts/hooks`.
- Keep `google*.html` (Search Console verification) at the root; `site_check.py` fails without it. It is not in the sitemap.
- **After a push**, remind the user to request indexing of new or changed pages in Google Search Console (URL inspection, then "Request indexing"). This is a manual action for the user: flag it explicitly.
